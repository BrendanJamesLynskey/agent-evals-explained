<Layer kind="concept">

The animation is one task in the style of [SWE-bench](https://arxiv.org/abs/2310.06770), the benchmark most coding agents are quoted on. The agent gets a repository at a **base commit** and an **issue** written by a person. It reads, edits and runs things, then stops; its **patch** is the difference between the repository it leaves and the base commit. Only then are the **hidden tests** added and run. SWE-bench's dataset names them: **FAIL_TO_PASS** tests were written with the real fix and fail on the base commit, so they check the issue is fixed; **PASS_TO_PASS** tests passed before, so they check nothing else broke. The task is **resolved** only if every one of both kinds passes.

<span id="ev-patches" />

The three patches show what the grader can and cannot see. The right fix passes. A patch that breaks `sub()` while fixing `add()` fails a PASS_TO_PASS test, even though the agent said it had fixed the arithmetic. The overfit patch, `return a * b - 1`, gives $\text{add}(2, 3) = 5$ and nothing else right: the thorough hidden tests catch it, but with the **weak** tests (only the example from the issue) it is scored as <V of="verdict.overfit|weak" fmt="raw" />. A grader is only as good as its tests, and the agent's own report counts for nothing.

<Layer kind="maths">

<span id="ev-grader-bias" />

Grading turns each task into one bit, $x_t \in \{0, 1\}$, and the score is their mean, $\hat p = \frac{1}{T}\sum_t x_t$. Every grader error moves that bit. If a fraction $f_+$ of failed tasks is wrongly passed (weak tests) and a fraction $f_-$ of solved ones is wrongly failed (flaky tests, a broken environment), the expected score is $p(1 - f_-) + (1-p)f_+$ instead of $p$. A biased grader is not noise that more tasks average away: chapter 4's intervals would tighten around the wrong number.

<Remember>

- SWE-bench-style grading: hidden FAIL_TO_PASS tests check the fix; PASS_TO_PASS tests check nothing else broke.
- Weak tests pass wrong patches; the agent's own claim is worth nothing.
- Every benchmark has known issues: weak graders, the harness, contamination.
- A biased grader is not noise: more tasks do not average it away.
